# Quillmate — 本地全自动 AI 小说工作台

Quillmate 是一个跑在本地的长篇小说生产工作台。启动服务后用浏览器打开，就能完成 **立项 → 世界观架构 → 角色设定 → 章节细纲 → 自动写作 → 审校 → 导出 / 发布** 的全流程。

- **本地优先**：小说、设定、登录会话都保存在你本机的 `data/` 目录，不依赖云端数据库。
- **模型自由**：兼容任意 OpenAI 风格接口（DeepSeek、通义千问、OpenAI、Ollama、vLLM 等），未配置时自动使用离线 `mock` 模式跑通流程。单次输出预算分标准 / 高输出 / 超大输出三档，JSON 被截断时自动在档位内提高预算或拆分批次。
- **浏览器内配置模型**：右上角「模型设置」填写 API Key、切换服务商与模型，保存后立即生效，无需重启；输出档位用滑杆选择，默认「高输出档 16384 Tokens」。
- **浏览器工作台**：多项目作品库、人物卡、章节编辑器与实时任务台，全部在一个 Next.js 应用里；任务日志按聊天消息逐条展示，并配一个随任务状态变化的 emoji 助手。
- **双主题界面**：浅色 / 深色主题一键切换，首屏按上次选择直接绘制、不闪白，选择只保存在本机浏览器。
- **自动发布**：内置番茄小说 Playwright 适配器，扫码登录一次后自动建章、填表、存草稿或提交发布。

> 这是可运行的骨架版本：核心链路已经打通，发布选择器需要按番茄后台的实际页面校验，详见「番茄小说自动发布」。

## 核心能力

| 模块 | 说明 |
| --- | --- |
| 作品库 | 创建 / 删除小说项目，展示章节进度、字数与更新时间 |
| 模型设置 | 浏览器内填写 API Key、选择服务商与模型，保存即热切换；密钥本机保存、脱敏回显；单次最大 Tokens 用三档滑杆统一管理输出预算 |
| 架构 Agent | 分三阶段生成：先世界观与主线，再分批生成章节细纲（标准/高输出档每批 10 章，超大输出档每批 20 章），最后分批生成结构化计划台账；某一批被截断会自动拆半重试。大纲、人物与计划台账全部通过校验后才统一提交，中途失败不覆盖旧资料 |
| 大纲扩充 | 章节不够时按需补充细纲，续排后续章节并同步登记计划台账；`plan.json`、`outline.md`、计划台账与项目元数据在一次提交内同步，已写正文与设定保持不变 |

| 角色 Agent | 生成结构化人物卡：目标、缺陷、关系、弧光、说话口吻；重新生成时保留用户手动编辑或旧版人物卡 |

| 写作 Agent | 逐章写作，自动注入世界观、人物卡、前情摘要、本章细纲、本章计划台账、事实台账，以及按相关度检索的长期记忆与剧情台账；三种台账冲突时以事实台账为准 |
| 连续性闸门 | 写后抽取事实并比对台账；严重冲突自动定点修复（正常写作最多三轮），仍不通过则新稿不写入正文，原稿保留并暂停后续自动写作 |

| 事实台账 | `canon.json` 记录人物生死、物品归属、时间线与硬规则；生成架构时先用人物卡建立“状态未知”的初始人物基线，物品/期限/规则由正文抽取补充；旧作品可从已写正文重建 |
| 分层记忆 | 全书 / 分卷 / 章节 / 动态检索四层；写作前只注入与本章相关的历史摘要、人物、规则和未回收伏笔，带 Token 预算与来源；支持离线基础记忆、AI 重建和人工修正 |
| 剧情台账 | 人物动态状态历史、人物关系、剧情事件因果与伏笔生命周期；查询任意章节时间点的人物状态；AI 只能给出伏笔回收候选，必须由作者确认 |

## 输出预算与截断恢复

单次最大 Tokens 只提供三个档位，在「模型设置」用一条滑杆选择：

| 档位 | Tokens | 适合场景 |
| --- | --- | --- |
| 标准档 | 8192 | 短章节、审校、字段较少的 JSON 抽取 |
| 高输出档（默认） | 16384 | 日常长篇写作、章节细纲和人物卡 |
| 超大输出档 | 32768 | 全书架构、大型分批计划台账；需模型支持该额度 |

- 旧配置里的任意 `maxTokens` 会在读取时归一到最近的档位；两档等距时取更高档，避免旧配置被意外降额。`.env.local` 的 `LLM_MAX_TOKENS` 也按同一规则归一。
- 输出被截断（`finish_reason` 为 `length`、`max_tokens`、`incomplete` 等）时，工作台会在所选档位内最多提高两次预算重试。章节细纲和计划台账若仍被截断，会把当前批次拆成两半分别生成，而不是重做整本架构。
- 截断与非法 JSON 分开处理：截断只提高预算，不会拿残缺内容去做普通修复。非法 JSON 先在本地宽容修复（Markdown 代码围栏、尾随逗号、数组/对象之间漏逗号），失败后再用低温请求模型只返回修正后的 JSON；两次都不合法才报错。
- 模型供应商不支持所选额度时，请求会明确报错并提示降低档位或更换模型，不会静默降级。
- 推理型模型把额度耗在思考上导致正文为空时，会在当前档位内提高预算重试一次；仍为空时建议换用非推理模型。

## 连续性防错

每写完或重写一章，平台会依次执行：

1. 从本章正文抽取人物生死、物品归属、时间线等事实，合并进 `canon.json`；
2. 先做确定性检查：死亡人物、章首/大段重复、大纲偏离、同一时间多地点、已死人物参与后续事件、复活缺少事件依据、伏笔回收早于埋设、事件关联断裂；再用「写作前台账 + 人物卡 + 剧情台账 + 前几章结尾/摘要 + 本章正文」做 11 维度审校，问题必须附带原文证据；
3. 发现严重冲突时，让模型只修冲突段落，最多三轮；
4. 仍不通过则新稿不写入 `chapters/`：新写章节保持未写状态，重写章节保留原稿；新稿存入 `drafts/`，在「连续性」页列为「未采用草稿」，并暂停后续自动写作。

只有通过连续性检查的章节才会计入已写、导出和发布，避免已知的严重矛盾进入正文。未通过时可在 `drafts/` 查看被拒草稿，按审校记录人工修改后保存，或调整要求重新生成；也可以在「连续性 → 章节审校」对某份未采用草稿点「交给修复 Agent」，系统会按草稿现有审校问题重新抽取事实、审校，并最多自动修 2 轮。通过验收后自动写入正文，重写稿会先备份原稿；仍未通过则更新草稿并保留原正文。

重写时可以在「AI 任务台」勾选「按照章节审校重写」：系统会读取目标章节上一版审校记录中的严重问题，注入写作和修复提示词。旧记录可能已经过时，提示词会要求模型只处理新稿中仍然存在的问题，不会为了过时的误报强行改剧情。

已写的旧作品可以在「连续性」页点「重建事实台账」，逐章从正文重新抽取事实并更新摘要；这个操作不会改动正文。AI 任务台的「总体审校全书」会逐章重建临时台账并检查全书，同样只读；原始报告写入项目根目录 `audit.md`，并可在「连续性 → 总体审校」按章节查看严重/建议与证据。

总体审校把问题分为三档：**严重**（硬矛盾，必须修）、**建议**（衔接或表达问题，值得修）、**可忽略**（措辞、文风、细节偏好或证据不足，可改可不改）。总体审校的章节卡片可以直接点「定点修复正文」：只把严重和建议交给修复模型做局部修改，可忽略项只展示不修。修复稿先作为候选稿独立抽取事实、重跑审校并检查回归问题，通过验收后才备份原稿并写回正文；未通过时原正文保持不变，候选稿保存在 `drafts/`，遗留问题进入章节审校记录便于继续处理。默认开启「修复后自动继续下一章」：从当前章往后逐章修复，跟随当前的「全部 / 严重 / 可忽略」筛选，自动跳过没有可修复问题和已修复的章节，适合一次清理整份总体审校记录。修复后的章节会标记为「已修复，待重审」，暂时隐藏修复按钮，避免重复按旧快照修改；总体审校报告是修复前的快照，重新运行总体审校后才会更新结论。批量修复运行时，任务台会显示「暂停定点修复」按钮：暂停不会中断当前章节，会等该章完成检查并处理完再停止，已完成的章节保留，剩余章节稍后可再次启动。

「连续性 → 遗留修复」会把定点修复后仍未解决的严重问题按章节汇总，并附带同章的建议和可忽略项，每章提供「定点修复」按钮。这个按钮使用该章当前审校记录，不依赖总体审校报告；修复同样走候选稿验收，通过后备份原稿并写回正文，完成后重新检查并把新的遗留问题写回章节审校。

重写章节通过后会自动对账台账：如果某个人物的状态只由被覆盖的旧稿确立、且新正文里已不再出现该人物，会降级为「状态未知」，避免旧的死亡事实继续约束后续写作。

重写或定点修复旧章节时，写作、事实抽取和连续性检查只使用“截至该章已确立”的台账；后文才发生的死亡、物品变化和时间线只作为下一章衔接参考，不再算作前章矛盾。修复结果仍会合并回完整台账，后文事实不会丢失。

增强审校里的确定性检查只是“待核实线索”：例如同一时间出现多个地点、正文大段复述旧章、细纲关键事件在正文中没有对应，都会先交给审校模型结合上下文判断。数据级严重问题（例如伏笔回收章节早于埋设章节）会强制保留，不允许模型静默忽略。审校和修复提示词都明确要求：不得通过修改既定事实或台账来让章节过关；冲突时只能指出正文需要改。定点修复后仍会重新抽取事实、重跑剧情台账和全部审校维度，原稿继续备份到 `drafts/`，并保留 `ai-repair` 章节版本。

### 定点修复：局部补丁与候选稿验收

定点修复不会让模型重写整章，而是要求它返回「原文片段 → 替换片段」的结构化补丁。补丁必须命中授权段落和原文锚点；重叠、越界、锚点不存在或改到未授权章节都会被拒绝。修复结果先作为候选稿保存到 `drafts/`，再独立抽取事实、重跑审校，并对比修复前后的因果结构：

- 原有严重问题必须全部解决，且不能新增严重问题；
- 新增警告级问题在严格模式下也会阻断；标准模式只阻断事实类警告；
- 规则拓展、解释不足和表达建议只记录，不作为剧情矛盾；
- 任意一步事实抽取或审校失败，都不会写回正文。

通过验收后才写入正文，原稿继续备份在 `drafts/`；如果仍有遗留问题，会写回章节审校记录。单章修复最多两轮：第一轮修原问题，若独立确认出现新增严重问题，第二轮只修这些新增问题，不会重做已解决的问题。

### 跨章修复需要作者确认

如果冲突根因不在本章，系统会生成 2–4 个互斥方案，例如只改本章，或连同根因章节一起改，并列出每个方案涉及修改的章节和必须保留的原文锚点。任务台会弹出确认框，作者选好方案后才会允许修改此前章节；未确认时，跨章原文只用于分析，不会被改动。确认后系统按同一修复来源重新启动任务，此前章节的修改也要逐章独立审校并通过验收。

## 提示词版本与调用记录

模型设置页下半部分新增「提示词版本」：

- 每个 Agent（架构、角色、写作、事实抽取、审校、修复等）都有稳定的内置版本号，定义在 `lib/prompt-registry.ts`。修改提示词代码时应同步提升对应版本。
- 可以在设置页为某个 Agent 创建「附加规则」版本，选择追加到 system 或 user 提示词末尾。附加规则只追加，不替换章节正文、JSON 约束和变量，避免把动态提示词拼装改坏。
- 历史版本不可变；可以查看每条规则、启用旧版本，或一键恢复内置提示词。创建和切换会立即影响之后的新任务，不会改写已写正文。
- 每次真实模型调用都会把 Agent、提示词版本、提示词 SHA-256 指纹、模型、温度、max tokens、章节号和消息字符数追加到 `data/prompt-usage.jsonl`。只记录元数据，不保存 API Key、完整提示词或正文。Mock 模式不产生记录。
- 总体审校报告头会写入模型、温度、最大 tokens 和审校提示词版本，便于回溯“这份结论由哪套提示词产生”。
- 离线回归测试集覆盖死亡人物、时间地点冲突、伏笔、章节重复和大纲偏离等典型场景，并校验审校提示词始终包含 11 个维度、证据要求和“不得改台账”约束。真实模型效果回归需要 API 费用，不自动执行。

## 版本与一致性

- 章节页右上角的「历史版本」会列出每次正式修改：`AI 写作`、`AI 重写`、`AI 修复`、`手动保存`、`版本恢复` 和 `系统/导入`。可以查看行级差异，或恢复任意版本；恢复前会再记录一条新版本，旧稿不会被删除。
- 恢复旧正文不会自动回滚事实台账和审校记录；恢复后建议重新运行章节审校或重建事实台账。
- 重新生成架构时，大纲、世界观、主线大纲、计划台账和人物卡全部生成并通过校验后才会一次性写入；中途失败不会覆盖原有资料。手动编辑或旧版人物卡会保留，AI 生成的人物卡会更新。只有项目没有已写正文且事实台账为空时，才会用最终人物卡建立初始人物基线；已有正文、手工台账或真实事实不会覆盖。
- 总览页的「数据一致性」可以检查章节编号、正文文件、事实台账，以及 `plan.json` 与 `outline.md` 的同步状态。能确定的缺失章节可以一键补全；标题不一致、孤儿章节等会提示人工确认，不会静默覆盖用户内容。

## 长篇分层记忆

长篇不能只依赖最近几章摘要。工作台现在维护四层记忆，并在每次写作/重写前按当前章节相关度检索：

- **全书记忆**：主线、核心矛盾、最终目标、核心人物、核心规则和故事梗概。
- **分卷记忆**：从 `outline.md` 的「第X卷（a-b章）」解析卷范围；卷目标、主要事件、人物阶段变化、本卷冲突和未回收伏笔按章节记忆自动聚合。
- **章节记忆**：摘要、事件、出场人物、人物行动、时间、地点、章末状态、新增设定、埋设/回收伏笔。只保存摘要和结构化字段，不复制正文。
- **动态检索**：用当前章节标题/摘要/关键事件分词，匹配历史章节、人物、物品、规则和未回收伏笔；默认约 4000 tokens 预算，超预算按优先级截断，并标注来源章节。

记忆的生成方式：

- **基础记忆**：不调用模型。读取已有章节摘要、事实台账中该章确立的人物/物品/期限，以及大纲里明确写出的伏笔回收点。旧项目升级后即可用。
- **AI 重建**：在「记忆」页手动启动 `memory` 任务，逐章抽取更完整的事件、时间、地点、章末状态和伏笔；全部章节成功后才一次提交，失败时已有记忆不变。
- **自动更新**：新写、重写或定点修复通过连续性检查后，更新该章记忆并重新聚合分卷/全书。记忆保存失败只记录日志，不回滚正文和台账，旧记忆保持原样。
- **人工修正**：全书、分卷和章节记忆都能在「记忆」页编辑；人工条目标记为 `manual`，AI 重建不会覆盖它们。

检索结果会作为 `【长期记忆】` 注入写作提示词，并明确要求：记忆中没有记录的人物、物品、规则和事件不得补写成既定事实；记忆与事实台账冲突时以台账为准。重写较早章节后，后续章节记忆不会自动重抽，可再运行一次「重建完整记忆」。

## 人物状态、剧情事件与伏笔

「剧情台账」页把静态人物卡之外的变化单独记录，写入 `.md` 正文时不复制全文，只保存结构化事实：

- **人物动态状态**：按章节保存快照，包括身份、故事年龄、位置、身体状态、生死、能力、目标、掌握的信息、阵营和重要经历；查询第 N 章时取每人在 N 章前最近的快照。状态变更通过 `eventIds` 关联剧情事件。
- **人物关系**：记录双方、关系类型、当前状态和确立章节；可按章节时间点查看关系变化。
- **剧情事件**：记录事件名、时间、地点、参与者、起因、过程、结果、后续影响和关联事件；支持按章节时间线、按人物查询事件历史。
- **伏笔生命周期**：已埋设 / 发展中 / 待回收 / 已回收 / 已废弃；记录埋设章节、相关人物、预计回收范围、关联事件和回收说明。正文提到可能回收时只生成“回收候选”，AI 不会自动把伏笔改成已回收，作者在页面上确认后才生效；超出预计回收章节会标为超期。

写作和重写前会检索截至上一章的人物状态、关系、相关事件和未回收伏笔，作为 `【剧情台账】` 注入提示词，并明确要求人物行为符合当前生死/位置/能力/掌握信息、不得虚构关系和因果。写作或重建后还会检查：同一时间同一人物是否出现在多个地点、已死人物是否出现在后续事件、复活/假死是否缺少关联事件、事件关联是否断裂、伏笔是否回收早于埋设。

离线「生成基础台账」用现有章节记忆、事实台账和大纲生成，不调用模型；「重建记忆与台账（AI）」复用同一次事实抽取，不额外增加模型调用。记忆/台账保存失败只记录日志，不回滚已经通过检查的正文和事实台账。

## 计划台账（创作计划）

架构和续排大纲时会同时生成一份结构化「计划台账」，文件后端写入 `plan-ledger.json`，SQLite 模式存于独立的 `plan_ledgers` 表。它与事实台账、剧情台账物理分离：

- **登记内容**：计划事件（章节、参与者、前提、经过、预期结果、影响、关联事件）、人物变化、计划伏笔、时间线约束、物品持有人变化和偏离记录。
- **状态**：未执行 / 部分实现 / 已确认实现 / 已偏离计划 / 已取消。刚生成时一律是「未执行」，不代表已经发生。
- **写作注入**：写第 N 章前只注入该章尚未实现的计划（未执行、部分实现或已偏离），并明确标注「本章计划台账（创作计划，不代表已经发生）」；正文没有写出的计划内容不能当成既定事实。
- **事后对账**：新写、重写、定点修复或重建台账后，用该章正文抽取结果、章节记忆和剧情事件计算相似度，更新计划状态并记录偏离（计划要求、实际正文和所在章节）。对账只更新计划台账，不改写正文。
- **冲突优先级**：事实台账 > 实际剧情台账 / 长期记忆 > 计划台账。已确认事实不能被计划覆盖，写作和审校提示词都带这条约束。
- **失败保护**：计划台账保存失败只记录日志，不回滚已经通过连续性检查的正文和其他台账，旧计划台账保持原样。

## SQLite 数据层、迁移与备份

结构化数据支持 SQLite 后端，采用混合存储：

- **SQLite**：项目元数据、章节大纲与状态、人物卡、事实台账、审校记录、章节版本元数据、任务与日志、发布日志、永久去重台账、长期记忆（`book_memory`、`volume_memories`、`chapter_memories`）、剧情台账（`story_character_states`、`story_relations`、`story_events`、`story_foreshadows`、`story_meta`），以及计划台账（`plan_ledgers`）。
- **Markdown/文件**：章节正文、`world.md`、`outline.md`、`audit.md`、`drafts/`、版本正文文件、导出文件；文件后端的分层记忆、剧情台账和计划台账分别保存在 `memory.json`、`story.json`、`plan-ledger.json`。
- 数据库默认位于 `data/db/quillmate.sqlite`，开启 WAL、外键和忙等待；章节正文和版本正文不会被复制进数据库。
- Schema 已升级到 v4：v2 新增记忆表，v3 新增人物状态/关系/事件/伏笔表，v4 新增独立的计划台账表；只追加、不删除或修改旧列，已有数据库启动时自动追加，无需重新迁移项目。
- 模型设置仍保留在 `data/settings.json`，避免在密钥加密完成前把明文 Key 再复制进数据库；提示词附加规则和使用记录分别保存在全局 `data/prompts.json`、`data/prompt-usage.jsonl`，不进入项目数据；`model_configs` 表留到密钥安全阶段再迁移。

存储模式由 `QUILLMATE_STORAGE` 控制：

- `auto`（默认）：数据库存在且可用时使用 SQLite，否则继续文件模式。
- `file`：强制使用旧 JSON/Markdown 文件后端。
- `sqlite`：强制使用 SQLite；数据库不存在时会创建空库，正式项目请先迁移。

首次从旧数据升级：

```bash
# 先停止开发服务器，确认没有后台任务在运行
npm run db:migrate
npm run db:verify
```

`db:migrate` 会先创建完整快照（`data/backups/pre-sqlite-*`），再逐项目迁移；任一项目失败会回滚数据库，原 JSON/Markdown 不会被修改。迁移完成后应用自动使用 SQLite。

完整备份与恢复：

```bash
npm run db:backup                  # 备份数据库 + projects/jobs/settings
npm run db:restore -- <备份目录> --yes
npm run db:rollback -- --yes       # 回到最近一次迁移前快照，并移除当前数据库
```

`db:backup` 生成的是完整备份目录，因为章节正文仍在 Markdown 文件里；只复制 `.sqlite` 文件不能恢复正文。`db:rollback` 会把迁移后的数据保留为 `data/*.before-rollback-*`，避免误删迁移期间的新改动。

迁移失败、数据库事务回滚、备份恢复和文件/SQLite 读取一致性都有自动化测试覆盖。真实模型调用和番茄发布不受数据层切换影响。

## 技术栈

- **Next.js 16（App Router，Turbopack 构建）+ React 19 + TypeScript**
- **OpenAI Node SDK**：调用任意 OpenAI 兼容接口
- **Playwright**：番茄小说发布自动化，持久化浏览器会话
- **SQLite + Markdown 混合存储**：结构化元数据、台账、审校、任务、发布状态、分层记忆、剧情台账和计划台账在 `data/db/quillmate.sqlite`；章节正文、世界观、大纲、审校报告和版本正文仍在 Markdown/文件里
- **文件兼容后端**：未迁移项目仍可继续使用 JSON 文件；`QUILLMATE_STORAGE=file|sqlite|auto` 切换
- **react-markdown + remark-gfm**：世界观与大纲渲染
- **依赖安全**：生产依赖 `npm audit --omit=dev` 为 0；完整审计仍有开发依赖链的 picomatch 告警，上游暂无修复版本，不影响生产运行时

## 快速开始

要求：Node.js ≥ 22.5（开发验证使用 Node 24.12）。SQLite 后端使用 Node 内置 `node:sqlite`，因此不再支持 Node 18/20；仍可使用 `QUILLMATE_STORAGE=file` 运行旧文件后端。

```bash
npm install
npm run dev
```

番茄自动发布默认**复用系统 Edge**，无需额外下载浏览器。如果系统没有 Edge，可以改用 Playwright 自带 Chromium：在 `.env.local` 设置 `BROWSER_CHANNEL=chromium`，再执行 `npx playwright install chromium`。只做本地导出则完全不需要浏览器。

打开 http://localhost:3000 。右上角开关可在浅色 / 深色主题间切换，选择只保存在浏览器。

首次启动无需任何 API Key：工作台会使用 `mock` 模式生成示例架构、角色与占位章节，用于验证全流程。

需要真实模型时，点右上角「模型设置」，选服务商预设、填写 API Key，点「保存并热切换」即可，不用重启服务。

建议操作顺序：

1. 在作品库填写书名与一句创意，点击「创建工作台」。
2. 进入工作台，点右侧「生成架构与角色」。任务台会依次显示世界观与主线、分批章节细纲、分批计划台账和人物卡；每批进度和截断重试都会写进日志。
3. 在「总览」查看世界观、大纲与章节细纲。
4. 在「角色设定」检查人物卡；点「编辑」用可视化表单修改，改完点「保存全部」。
5. 在「章节」点「写下一章」，或回任务台一次写多章；章节不够时在任务台点「补充 N 章大纲」续排，无需重新生成整本架构。
6. 在「记忆」页可以生成基础记忆、预览下一章会检索到的历史上下文；需要更细的事件/伏笔时再运行「重建完整记忆（AI）」。
7. 在「剧情台账」页按章节查看人物动态状态、关系、事件时间线和伏笔状态；可以离线生成基础台账、人工修正，或运行「重建记忆与台账（AI）」。伏笔回收必须由作者确认。
8. 需要固定创作规范时，在「模型设置 → 提示词版本」为写作或审校 Agent 添加附加规则；可查看历史、启用旧版或恢复内置。
9. 如果使用推理型模型，或经常看到 JSON 截断提示，在「模型设置」把单次最大 Tokens 切到「高输出档」或「超大输出档」。
10. 在「发布」导出全书 Markdown，或登录番茄后自动发布。

## 开发与测试

```bash
npm run typecheck     # TypeScript 类型检查
npm run lint          # ESLint
npm run test          # Vitest 单元 / 集成测试
npm run test:coverage # Vitest + 覆盖率报告（coverage/）
npm run test:real     # 真实模型测试，默认跳过，需显式授权
npm run build         # Next.js 生产构建
npm audit --omit=dev  # 生产依赖漏洞审计
npm audit             # 含开发依赖的完整审计
npm run db:migrate  # JSON/文件迁移到 SQLite
npm run db:verify   # 数据库完整性与项目读取校验
npm run db:backup   # 完整备份（数据库 + 项目文件）
npm run db:restore  # 从完整备份恢复
npm run db:rollback # 回滚到迁移前快照
```

CI 位于 `.github/workflows/ci.yml`，在 push 到 `main` 和 Pull Request 时执行 `npm ci → lint → typecheck → test:coverage → build`，并上传 `coverage/` 报告。CI 不配置 API Key，不调用真实模型，也不执行真实番茄发布。

当前生产依赖审计为 0；完整 `npm audit` 仍会报告开发依赖（ESLint / Vitest 的 picomatch 链路）的 High 告警。该链路只用于本地开发和测试工具，上游暂未发布修复版本，不能通过降级或忽略来消除。

`@emnapi/core` 和 `@emnapi/runtime` 以固定版本保留在开发依赖中：npm 在 Windows 上重新生成 lockfile 时可能丢失 Linux 可选依赖，导致 CI 的 `npm ci` 报 lockfile 不同步；不要随意移除这两项。

真实模型测试默认跳过；确认要消耗 API 费用后再显式开启：

```bash
# Windows PowerShell
$env:QUILLMATE_REAL_MODEL_TESTS="1"; $env:LLM_PROVIDER="openai-compatible"; $env:LLM_API_KEY="sk-..."; npm run test:real
```

数据安全行为：

- 所有 JSON 与正文写入都先写同目录临时文件再 rename，避免进程中断留下半截文件。
- 覆盖 `project.json`、`plan.json`、`state.json`、`canon.json`、`characters.json`、`publish-ledger.json`、`world.md`、`outline.md`、`audit.md` 与章节正文前，会自动备份到 `data/projects/<slug>/backups/`，每个文件保留最近 20 份。
- 文件损坏会直接抛错并返回明确错误，不会用空数据覆盖原文件；只有“文件确实不存在”才按缺失处理。
- 事实抽取连续失败会重试 3 次；仍失败时章节不通过、正文不写入、台账不推进，草稿保留在 `drafts/`，任务进入可重试的暂停状态。
- 重建事实台账使用内存临时台账，只有全部章节成功并通过校验后才统一提交；任一章节失败都会保留原台账与摘要。
- 发布日志（`state.json` 中最多 100 条）与永久发布台账（`publish-ledger.json`）分离；清空或裁剪日志不会导致已发布章节重复提交。点击确认后无法确认结果的章节记为“待人工确认”，不会自动重发。
- 架构生成（大纲、世界观、主线与人物）全部成功并通过校验后才统一提交；提交前先快照目标文件，任一写入失败会按快照回滚，不会留下“新大纲 + 旧人物”的半成品。
- 补充章节时 `plan.json`、`outline.md` 与项目元数据一次提交；主线大纲只追加缺失章节，不改写用户已有内容。总览页的“数据一致性”检查只读，自动修复也只补缺失章节。
- 章节正文被正式覆盖前，必须先成功写入 `versions/<章号>/` 版本记录；版本记录失败时旧正文保持不变。恢复旧版本会新增一条 `restore` 版本，并清除已不匹配的审校/修复记录；事实台账不会自动回滚，恢复后建议重新审校或重建台账。旧项目如果已有正文但还没有版本，第一次覆盖前会自动建立原文基线。
- SQLite 模式使用事务更新项目、章节状态、人物、台账、审校、任务和发布台账；迁移前创建完整快照，迁移失败回滚并删除半成品数据库。数据库文件或完整性校验失败时会拒绝继续使用，不会用空数据覆盖原记录。
- 数据库完整备份同时包含 `data/db/quillmate.sqlite` 与 `projects/`、`jobs/`、`settings.json`；只恢复 `.sqlite` 不会恢复 Markdown 正文。
- 长期记忆使用独立的 `memory.json` 原子写入或 SQLite 事务提交；记忆保存失败不会回滚已经通过检查的正文和台账，也不会覆盖旧记忆。AI 重建任务只有全部章节成功后才提交，手工修正的章节/分卷/全书条目不会被覆盖。
- 剧情台账使用 `story.json` 原子写入或 SQLite 事务提交；保存失败同样不回滚正文和事实台账。人工删除的基础/自动记录会写入抑止 ID，避免下次离线 seed 时被重新补回；手工条目在 AI 重建时保留。伏笔“已回收”只能由作者确认，AI 只记录候选。
- 提示词附加规则使用临时文件 + rename 原子替换；损坏时写作任务继续使用内置提示词并记录警告。模型调用记录只追加元数据，不含 API Key、正文或完整提示词。
- 项目 slug 和任务 ID 在拼接任何磁盘路径前统一校验；非法 `../`、非 UUID 任务 ID 会被拒绝，版本记录中的文件路径也必须位于项目目录内。
- 所有写 API 都检查同源来源；删除项目、清空发布日志、恢复章节版本、删除剧情台账记录和启动番茄发布任务都需要服务端二次确认，不能只依赖前端按钮。
- API 错误响应会脱敏 API Key、Bearer 令牌和本地绝对路径；设置响应不缓存且只返回 Key 的掩码。`settings.json` 使用 `0600` 权限和原子写入。
- 番茄发布在启动浏览器前检查书名、作品 ID、章节号、重复序号、标题、正文和自动提交字数；登录态、网络异常、页面结构变化和提交结果不明会分别归类并给出排查提示。

## 接入真实模型

### 方式一：浏览器设置（推荐）

点右上角「模型设置」：

1. 选择一个预设（DeepSeek / OpenAI / 通义千问 / Ollama），或手动填写接口地址和模型名。
2. 填写 API Key，可先点「测试连接」验证是否可用。
3. 用「单次最大 Tokens」滑杆选择输出档位；日常写作保持「高输出档」，全书架构或大型计划台账再切「超大输出档」。
4. 点「保存并热切换」，后续生成任务立即使用新配置，无需重启。

配置保存在 `data/settings.json`，优先级高于 `.env.local`。页面只回显脱敏后的 Key 尾号；清除密钥后会回到 mock 模式。该文件包含明文密钥，已在 `.gitignore` 中忽略，请勿分享整个 `data/` 目录。

### 方式二：.env.local

没有保存过页面设置时，会读取环境变量。复制 `.env.example` 为 `.env.local`，按所用服务填写：

```ini
LLM_PROVIDER=openai-compatible
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
LLM_API_KEY=sk-your-key
LLM_MAX_TOKENS=16384
```

`LLM_MAX_TOKENS` 会归一到 8192 / 16384 / 32768 三档，不填时默认 16384。页面保存的设置优先于环境变量。

常见服务示例：

| 服务 | LLM_BASE_URL | LLM_MODEL |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| DeepSeek 推理版 | `https://api.deepseek.com/v1` | `deepseek-reasoner` / `deepseek-flash`（建议「超大输出档」；模型不支持时请降低档位） |
| OpenAI | `https://api.openai.com/v1` | 任意可用模型 |
| Ollama | `http://localhost:11434/v1` | `qwen2.5:14b` 等 |
| vLLM / 其它 | 你的 OpenAI 兼容地址 | 已部署的模型名 |

使用 Ollama 时 API Key 可以填任意非空字符串（例如 `ollama`），OpenAI SDK 要求该字段存在。

修改 `.env.local` 后重启 `npm run dev`。页面任务日志会提示当前是否处于 mock 模式。

| GET | `/api/projects/[slug]/story?chapter=N&character=名字` | 读取剧情台账；按章节返回人物状态、关系、事件和伏笔，可按人物查历史 |
| PATCH | `/api/projects/[slug]/story` | 手工新增/修改/删除人物状态、关系、事件或伏笔；伏笔回收由作者确认 |
| GET | `/api/projects/[slug]/story/check` | 返回时间地点、死亡人物、复活依据、事件关联和伏笔生命周期检查 |
| GET | `/api/projects/[slug]/story/retrieve?chapter=N` | 预览第 N 章写作前会注入的剧情台账上下文 |
| POST | `/api/projects/[slug]/story/seed` | 用章节记忆/事实台账/大纲离线生成基础剧情台账（不调用模型） |
| POST | `/api/projects/[slug]/publish/records` | 人工确认待定章节：标记已发布或未发布（需 `confirm:true`） |
| GET | `/api/settings` | 读取模型设置（密钥脱敏） |
| PUT | `/api/settings` | 保存模型设置并热切换 |
| POST | `/api/settings/test` | 用当前表单参数测试模型连接 |
| GET | `/api/prompts` | 读取各 Agent 内置版本、附加规则历史、当前启用版本和最近模型调用记录 |
| POST | `/api/prompts` | 创建并默认启用一个附加提示词版本（可追加到 system/user） |
| PATCH | `/api/prompts` | 启用历史版本，或传 `activeId: null` 恢复内置提示词 |

任务类型：`plan`、`extend`、`write`、`rewrite`、`repair`、`recanon`、`memory`、`audit`、`export`、`fanqie-login`、`fanqie-publish`。其中 `extend` 用于补充章节大纲，`repair` 可按总体审校记录或章节审校遗留问题做单章/批量定点修复，`recanon` 用于从已写正文重建事实台账，`memory` 用于逐章重建长期记忆与剧情台账（全部成功才提交），`audit` 用于只读的总体审校。

文件模式下任务快照保存在 `data/jobs/<id>.json`；SQLite 模式下任务与日志保存在 `jobs`、`job_logs` 表。项目锁和跨进程控制文件始终在 `data/jobs/locks`、`data/jobs/control`。同一项目同一时间只允许一个任务，并发请求返回 409；Next.js 开发模式下页面与 API 可能在不同进程，因此锁和暂停/取消信号都通过文件共享。

服务重启后，仍在排队/运行的任务会标记为 `interrupted`，可在任务台点击「重试任务」按原参数重新执行（已写章节会跳过）。取消是协作式的：在章节或模型调用边界停止，已完成章节保留。任务默认最长 30 分钟，可用 `QUILLMATE_JOB_TIMEOUT_MS` 调整；单次模型请求超时用 `LLM_TIMEOUT_MS`（默认 3 分钟）。

## 番茄小说自动发布

适配器位于 `lib/publishers/fanqie.ts`，会打开番茄作家工作台：

- https://fanqienovel.com/main/writer/

流程：

1. 在「发布」页填写番茄后台里的**作品名**（也可填写 bookId），保存设置。
2. 点击「登录番茄」。服务会打开可见的 Edge 窗口并自动进入登录页，用番茄 App 扫码或手机验证码登录。登录成功后程序会识别登录 Cookie 并自动关闭窗口，最长等待 10 分钟；也可以手动关闭窗口保存会话。登录态保存在 `data/browser/fanqie/`，后续任务复用。
3. 默认关闭「自动提交」，先验证存草稿：点「发布 N 章」，适配器会逐章打开新建章节、填写章节序号、标题与正文、存草稿。
4. 正式提交时，适配器会点击「下一步」，选择「仅基础检测」，在发布设置中声明「使用 AI：是」，最后点击「确认提交」。番茄后台通常需要数十分钟到 1 小时审核上线。
5. 番茄要求每章正文不少于 1000 字，标题需要配合章节序号。适配器会在启动浏览器前预检书名、作品 ID、章节号、重复序号、标题、正文和字数；已成功提交的章节会写入 `publish-ledger.json` 永久台账，后续发布会自动跳过，避免重复上传；日志被裁剪或清空也不影响去重。
6. 如果点击「确认提交」后无法确认平台是否接收，该章会标记为「待人工确认」并暂停自动重发。请到番茄后台核对，然后在发布页点「标记已发布」或「标记未发布」。
7. 启动发布任务时服务端要求 `confirmPublish` 二次确认；绕过发布页直接调用任务接口会被拒绝。登录失效、网络异常、页面结构变化和提交结果不明会写入任务日志并附排查建议。

**选择器可配置**：发布页「高级：站点选择器」可以覆盖 `bookEntry / createChapter / titleInput / contentEditor / saveButton / publishButton / confirmButton`。其中 `bookEntry` 默认指向工作台的作品卡片 `.completion-book-item`；番茄后台改版后，按 F12 检查元素，填入新的 CSS 选择器或 `text=文案` 即可，无需改代码。

注意事项：

- 自动发布依赖第三方网页结构，**选择器未针对你的账号后台逐项验证前，请务必先用存草稿模式测试**。
- 平台可能要求验证码、实名认证或额外弹窗；适配器失败时会把截图写入 `data/publish-artifacts/`，便于排查。
- 账号登录会话相当于账号凭据，请勿把 `data/browser/` 提交到版本库或分享。
- 自动化发布可能违反平台规则或触发风控。请自行确认平台条款，控制频率，并对最终内容负责。

### 调整生成效果

- 所有提示词集中在 `lib/prompts.ts`，可直接修改文风、字数、JSON 字段要求；同时提升 `lib/prompt-registry.ts` 中对应 Agent 的版本号。
- 临时创作规范可以不改代码，在「模型设置 → 提示词版本」创建附加规则版本；历史版本可回滚，恢复到内置不会删除旧版本记录。

- 长篇记忆目前使用「最近 6 章摘要 + 分层记忆动态检索」。更长篇可以在 `lib/memory.ts` 的检索评分和 Token 预算基础上接入向量检索。

## 常见问题

**页面能打开，但生成的是示例内容？**  
还没有可用的模型配置：打开右上角「模型设置」填写 API Key 并保存即可，或按「接入真实模型」配置 `.env.local` 后重启。注意页面保存的设置优先级更高。

**任务失败提示「模型返回了空内容」？**  
多见于推理型模型（deepseek-flash、deepseek-reasoner 等）：它们会先耗一段输出额度“思考”，如果输出档位太小，额度会被思考用光，正文为空。工作台会在当前档位内自动提高预算重试一次；仍失败时，请到「模型设置」选择「高输出档」或「超大输出档」，或改用非推理的 `deepseek-chat`。

**提示「模型输出达到 Tokens 上限」怎么办？**  
这说明 `finish_reason` 是 `length` 一类的截断标记。架构、章节细纲批次和计划台账会自动拆小批次重试；如果仍报截断，把设置切到「超大输出档 32768」，或减少一次生成的内容。某些模型本身不支持 32768 输出，会直接提示降低档位，不会静默降级。

**模型返回的 JSON 不合法怎么办？**  
工作台会先本地宽容修复代码围栏、尾随逗号和漏写的逗号，再用低温请求模型只输出修正后的 JSON；两次都不合法时才会报错。可以重试任务，或在「模型设置」换用输出更稳定的模型。

**登录窗口刚打开就自己关了？**  
程序现在通过番茄的登录 Cookie 判断状态，不会再把宣传页误当成已登录。如果窗口仍立即关闭，任务日志会提示「检测到本机已保存番茄登录会话」，说明已有有效登录。需要重新登录时，可删除 `data/browser/fanqie/` 后再试。

**登录窗口一直不自动关闭？**  
说明尚未检测到登录成功，请确认已完成扫码或验证码登录；也可以手动关闭窗口，会话会保存到本地。

**点「登录番茄」没有弹出窗口？**  
默认使用系统 Edge。确认本机已安装 Edge，或在 `.env.local` 设置 `BROWSER_CHANNEL=chromium` 并执行 `npx playwright install chromium`。远程无桌面环境无法显示登录窗口；登录必须在有图形界面的本机完成。

**发布时报「找不到作品」或「找不到入口」？**  
先确认「发布」页的书名与番茄工作台完全一致（或填写 bookId），并确认登录的是同一账号。适配器现在从 https://fanqienovel.com/main/writer/ 的作品卡片进入；若界面再次改版，查看 `data/publish-artifacts/` 截图，到发布页高级设置里更新选择器。

**为什么发布前提示正文不足 1000 字？**  
番茄要求每章正文至少 1000 字。任务会在打开浏览器前检查并列出不满足的章节，补足后再发布即可。已经成功提交的章节会自动跳过，不会重复上传。

**怎么删除一部作品？**  
在作品库的卡片底部点「删除作品」，确认后会连同 `data/projects/<slug>/` 下的设定、章节和导出文件一起永久删除，无法恢复。重要作品建议先备份 `data/`。

**重新生成架构会删除已写章节吗？**  
不会删除 `chapters/*.md`，但会覆盖 `plan.json`、设定文件和计划台账，旧章节可能不再出现在新大纲里。重要项目建议先备份 `data/`。

**大纲里的章节写完了，想继续写怎么办？**  
在右侧「AI 任务台」找到「补充章节大纲」，填写要新增的章数（1–50），点「补充 N 章大纲」。程序会参考最近章节细纲、已写章节摘要和世界观，从当前最大章节号往后续排；已写正文、设定和世界观都不会被覆盖，规划章节数与计划台账会同步更新，新增章节也会以「补充章节（第 X–Y 章）」追加到总览的主线大纲末尾。补充时会避开已有章节标题；若模型仍返回重复标题，会自动改名。补充完成后再继续「自动写 N 章」即可。

**章节在编辑器里保存后就算「已写」吗？**  
有非空正文即计入已写章节，可参与导出与发布；清空正文不会自动回退状态。
